# ClinOps EMR — Whole-App UX Critique

## Anti-Patterns Verdict
Not generic slop — the clinical-green palette, Inter scale, NEWS2 workbench, and skeleton discipline show a real system. But it is slop-adjacent in exactly the banned places: side-stripe accent borders (border-l-4) on every clinical workbench, metric-card walls on every dashboard-class page, section-wide animate-pulse, a hardcoded "To Pharmacy" count of 0, two component kits and two brand greens (#00a651 auth vs #0d7c3f app) coexisting, and a one-click unconfirmed discharge. A clinician trusts the data model but pauses at the window dressing. Under-disciplined execution of a good system.

## Cognitive Load
Failed: single focus (dashboard stacks 4 content blocks), visual hierarchy (3 page-title sizes; nested cards), one thing at a time (vitals tab: 6 inputs + 2 selects + checkbox + save + undo), minimal choices (triage sidebar 6 tabs, SOAP sidebar 7 sub-tabs, AVPU 5, triage category 5, pharmacy nav 5, dashboard pipeline 5), working memory (status vocab differs per screen; /queue and /consultation-queue both exist).
Passed: chunking (vitals 3-col grid), grouping (sidebar sections), progressive disclosure (additional-vitals toggle).

## Priority Issues
1. **[P0] One-click "Complete & Discharge" with no confirmation** (consultation/page.tsx:515,1096). Most consequential action in the app fires directly with a toast + 1.5s redirect. Fix: route through ConfirmDialog (danger) showing patient name + disposition. Command: $impeccable harden
2. **[P0] Section-wide pulsing + zero prefers-reduced-motion** (nurse-station:243; ~15 pulsing elements; no reduced-motion anywhere; WCAG 2.3.3 risk). Fix: static red banner with one restrained beacon; pulse only escalation-worthy; gate all motion behind prefers-reduced-motion (PRODUCT.md promises this). Command: $impeccable animate
3. **[P1] Two coexisting component vocabularies + two brand greens** — shadcn Card/Button vs legacy bg-white border-[#becab7]/50 cards and hand-rolled buttons (PageLayout, DataTable, StatsRow, referrals, appointments, admissions, ward-round, receptionist); auth uses #00a651 while app uses #0d7c3f. Fix: delete legacy card/button set; standardize auth on clinical-primary. Command: $impeccable polish
4. **[P1] Side-stripe accent borders** (border-l-4: patients/[id]:261, triage:544, consultation:529+1082, chronic-care:237; DataTable hover:152; PatientBanner h-1 strip). Fix: full border + badge; hover = bg-muted/50 tint. Command: $impeccable polish
5. **[P1] Metric-card walls + fake number** — every dashboard-class page opens with 4-6 number cards; dashboard "To Pharmacy" hardcoded 0 (dashboard/page.tsx:130). Fix: remove hardcoded stage or wire real data; collapse/relocate stat rows below the primary work surface. Command: $impeccable layout

### Accessibility findings (from detector/evidence)
- **[P1] Icon-only close buttons** without aria-label: Modal.tsx:55 (every modal), auth password toggle (auth/page.tsx:107-124), consultation delete-diagnosis X (consultation:690).
- **[P1] Contrast fails**: sky-500 links on auth (2.77:1), white on #00a651 CTA (3.19:1), breadcrumb links at /70 opacity (2.57:1), text-gray-400 hints (2.42-2.54:1), amber-600 small text (3.19:1), muted-foreground on #fcf9f8 (4.40:1).
- **[P2] Modal is non-standard**: no role="dialog"/aria-modal/aria-labelledby, no focus trap or focus return (KeyboardShortcutsOverlay does it correctly — pattern exists).
- **[P2] Tabs keyboard-inert**: Tabs.tsx:47-78 sets roving tabIndex but no arrow-key handler; DataTable sortable th and onRowClick tr have no keyboard path.
- **[P2] 6 sites use native confirm()** instead of in-app ConfirmDialog (staff/[id]:95, roles:66, services:90, wards:103, departments:85, AppointmentActions:42).
- **[P2] No generateMetadata anywhere** — every route shares "ClinOps EMR" title; patients/page.tsx has no h1.
- **[P2] Missing live regions**: login error/success div (auth:143-156), DataTable load-error, live search dropdown in Topbar (no listbox/combobox semantics).
- **[P3] Touch targets**: TriageSidebar mobile tabs min-h-40px < 44px; globals.css text-xs exception collapses 44px rule.
- **[P3] Perf**: all 45 routes are "use client"; Topbar global search debounced fetch per keystroke with no cancellation.

## Persona Red Flags
**Alex (power user):** every xs table button forced to 44px tall by global min-height rule (globals.css:98) undoing density; vitals tab forces 6 fields before the collapsible block — re-expands every patient; dashboard opens on a metrics wall while his first action (patient lookup / queue) is 2 clicks deeper; three queue entry points with different labels.
**Sam (accessibility):** cannot switch tabs by keyboard (Tabs.tsx pointer-only); no reduced-motion support (full-section pulse = vestibular risk); amber-600 on white ~3.9:1 fails AA; gray-on-gray login error box; Modal lacks dialog semantics/focus trap; breadcrumb links at 2.57:1.
**Jordan (first-timer):** login CTA white-on-#00a651 at 3.19:1; icon-only close buttons; two greens with no explanation.

## Minor Observations
- DataTable draws column separators via divide-x on tr + hover:border-l-4 — a different table grammar than shadcn Table.
- Profile shows two competing identity blocks (gender chip + PatientBanner square).
- Dashboard "Awaiting Triage" and "Emergency" both link to /triage-queue.
- App shell main is bg-white; admin shell uses clinical-bg — two canvases.
- Pharmacy opens with 5 stat cards + 4 action buttons before dispensing is reachable.
- Patient search routes completed patients to /triage, never to the profile.
- Auth success message renders in the same gray box style as errors.

## Questions to Consider
1. The dashboard "To Pharmacy" is hardcoded 0 — if that number is fake, how many other numbers in the four stat-card walls are aspirational? Why does a task-first product open on a metrics wall instead of the queue or patient search?
2. There are two brand greens — if clinicians authenticate under one green and work under another, which is "the hospital green"?
3. Discharging a patient is one click with no confirm, yet ConfirmDialog exists — where else might high-stakes actions be silently unguarded?
